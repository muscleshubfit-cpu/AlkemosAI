# المرحلة 2 — دراسة النماذج المفتوحة

> إصدار: v1.2 · تاريخ: 2026-11-23 (UTC) · **الحالة: 🔄 التقييم العملي جارٍ ضمن المسار المجاني (D-11) — لا تعليق على D-2: محسوم بصفر التزام + قانون الجودة أولًا (ADR-0014)** · الوثيقة الحية لاكتشاف المرشحين صارت [`m2-discovery-report.md`](m2-discovery-report.md) وفق ADR-0022 (لا قائمة مسبقة — كل استبعاد موثق) · التبعيات: المرحلة 0 ✅ · M1 ✅ مغلقة (دفعة 12)
> **(دفعة 14):** فحوص العدّاء v2 (المراجعة النوعية §7 — إصلاحات الفحص الستة) منفذة ومثبتة 21/21، ومجسات v1.1 ثنائية اللغة هي نسخة التشغيل، والنتائج الخمس الموقعة أعيد تصحيحها محليًا (`evaluation/results/m2/rescore/`) — وقياس **Jais-3-7B أُطلق على GHA** (فئة ≤12B لا تنتظر تجدد Kaggle) وعدّة Kaggle جاهزة للفئة 20B+ فور التجديد 2026-11-28 ([دليل التشغيل](../03-infrastructure/kaggle-m2-runbook.md)).
> **تصحيح دفعة 13-ب:** حُذف شرط «الميزانية D-2» وأُزيلت خطة الاستئجار المدفوع (RunPod $0.34/س) من مسار التنفيذ — المزودون المدفوعون باب تصعيد D-13 فقط عند فشل المسار المجاني في بوابة الجودة، بقرار مالك (ADR-0014/0022). القنوات الفعلية: GHA CPU للفئة ≤12B (مُثبتة بـ4 قياسات) + Kaggle GPU للفئة 20B+ (دراسة [`../03-infrastructure/free-compute-resources-study.md`](../03-infrastructure/free-compute-resources-study.md)) + قناة GLM المجانية في بيئة الوكيل كمرجع سريع.

## 1. الهدف

ترتيب أفضل النماذج المفتوحة المرشحة لتخصصاتنا (عربية+إنجليزية، لياقة/تغذية/صحة، اتباع تعليمات، JSON صارم) مع بدائل احتياطية، بعد فحص التراخيص من مصادرها، ودراسة التكميم وMoE والتقطير.

## 2. معايير الفرز (مرتبة)

1. **الترخيص أولًا:** يسمح بالاستخدام التجاري + التعديل + التدريب على المخرجات (للتقطير) — بلا قيود إيرادات أو مجالات.
2. جودة العربية الفطرية (لا عبر ترجمة) — تُقاس على مهامنا.
3. جودة الإنجليزية والالتزام بالتعليمات وJSON الصارم (متطلب مهام خطط/أدوات خط الأساس).
4. الحجم والتكميم: قابل للتشغيل بـ 24–48GB VRAM (طبقة التقييم) وصولًا إلى 80GB (طبقة الجودة).
5. نضج الأدوات: vLLM/llama.cpp/Unsloth + مجتمع نشط.
6. توفر نسخة base (لتابع التدريب لاحقًا) وليس instruct فقط.

## 4. دراسة التقنيات (خلاصة أولية — تُعمّق عند التنفيذ)

- **التكميم (GGUF/AWQ/GPTQ):** يخفض التشغيل من 80GB إلى 24GB بفقد جودة طفيف معمومًا [موثق من مصادر عامة 2026] — إلزامي لخطة الـ$0.34/ساعة.
- **MoE:** معماريات A3B (3B نشطة) تمنح سرعة كبيرة بسعر صغير — مثالية للمهام المتوسطة؛ الحجم الكامل يستهلك ذاكرة كثيفة.
- **BitNet/1.58-bit:** واعدة نظريًا (تشغيل CPU) لكن نضجها الإنتاجي غير مثبت [غير متحقق] — تراقب دون اعتماد.
- **التقطير:** من نموذج كبير مدفوع إلى مرشحنا المفتوح — **محظور ترخيصيًا مع بعض المزودين**؛ يدرس مشروطًا بتراخيص المصدر (بند صريح في كل تقييم).

## 5. خطة التقييم العملي — المسار المجاني الساري (دفعة 13-ب)

القنوات المعتمدة (كلها مجانية — تفصيل الأرقام في دراسة الموارد):

1. **GHA CPU (سير `m2-battery-gguf` — يعمل):** GGUF Q4_K_M للفئة ≤12B — مُثبت فعليًا بأربعة قياسات (بطارية 36 كاملة لكل نموذج في 1.3–4.8 ساعات GHA) — **(دفعة 14): قياس Jais-3-7B (الأولوية الأولى — تقرير الاكتشاف §5.2) أُطلق على نفس السير** (GGUF رسمي `IFM/Jais-3-7B-GGUF` Q4_K_M بـ5.59GB مقيس 2026-11-23) — والسير صار يمرر `n_ctx` (كان مدخلًا معرفًا غير مستخدم — أُصلح) ويعمل بفحوص v2 ومجسات v1.1.
2. **Kaggle GPU (T4×2/P100 — 30س/أسبوع، تتجدد 2026-11-28):** للفئة 20B+ (27B/32B/35B-A3B) عبر llama.cpp بتمرير GPU — **(دفعة 14): العدّة جاهزة كاملة**: دفتر `scripts/kaggle/m2_kaggle_battery.py` (Run All — بلا أسرار — روابط GGUF مقيسة للمرشحين الأربعة) + [دليل التشغيل](../03-infrastructure/kaggle-m2-runbook.md) (ميزانية الحصة R-41 · استكشاف الأخطاء · بروتوكول إدماج النتائج). البطارية الكاملة نموذجًا في ~20–40 دقيقة [تقدير يُقاس أول جلسة].
3. **قناة GLM المجانية في بيئة الوكيل (قناة zai):** مرجع سريع — بطارية 36 في ~2.5 دقيقة (مقيس) + إعادة محاولة 429.
4. **ZeroGPU (~3.5 دقيقة إجمالية):** فحوص دخان للعمالقة (GLM-5.3-Flash) فقط.

```bash
# (أوامر مرجعية — العدّاء الفعلي scripts/m2_run_battery.py)
# GHA: سير m2-battery-gguf يدوي workflow_dispatch لكل GGUF
# Kaggle (فئة 20B+):
python3 scripts/m2_run_battery.py --channel gguf --model <path-27b-Q4_K_M.gguf> \
  --full --out-dir evaluation/results/m2/ --resume
# قناة الوكيل (مرجع):
python3 scripts/m2_run_battery.py --channel zai --tag GLM-4-plus-API --out-dir evaluation/results/m2/
```

**معيار النجاح:** 3–5 نماذج مقاسة على مهامنا الفعلية (تحقق جزئيًا: 5 قياسات عينة-36 منجزة) + المختصرون على البطارية الكاملة 162 + توصية مبررة لـD-5 (قرار مالك) + بديلان احتياطيان موثقا الاستبعاد.

**الاستئجار المدفوع (RunPod وغيره — $0.34/س لـRTX 4090 بتسعير 2026-11):** خارج مسار التنفيذ — يُفتح فقط عبر **D-13** إذا فشل المسار المجاني في بوابة الجودة، بقرار مالك موثق (مرجع الأسعار في COST_MODEL).

## 6. المهام التفصيلية

1. ✅ الفرز الأولي بمصادر مؤرخة (هذه الوثيقة + initial-screening) — **ثم superseded جزئيًا باكتشاف ADR-0022 المفتوح: [`m2-discovery-report.md`](m2-discovery-report.md) (v1.0 — 2026-11-22/23) هو المرجع الحي**.
2. 🔄 تحقق مباشر من الترخيص (منجز للمرشحين الفعليين عبر HF API — انظر جدول التراخيص في تقرير الاكتشاف §2؛ المتبقي: أي مرشح جديد يدخل القياس).
3. ✅ بناء بطارية التقييم — منجزة بمستوى أوسع من المخطط: **بطارية قانونية 162 حالة** (دفعة 8) + عينة طبقية حتمية 36 + **14 مجس مدرب** (دفعة 13-أ).
4. 🔄 التقييم العملي على القنوات المجانية: **5 قياسات عينة-36 منجزة** (Qwen3.5-9B · gemma-4-12b · gpt-oss-20b · Ornith-1.5-9B على GHA + glm-4-plus عبر قناة الوكيل) + مراجعة نوعية بالأدلة + **(دفعة 14): فحوص v2 منفذة والنتائج الخمس أعيد تصحيحها** (`rescore/` — منها اكتشاف موسع: gpt-oss بلا قناة إجابة في 13/36) + **قياس Jais-3-7B قيد التشغيل على GHA** — المتبقي: الفئة 20B+ على Kaggle بعد التجديد ثم البطارية الكاملة للمختصرين.
5. 🔄 قياس التكميم: فحوص v2 (دفعة 14) صارت تفرّق بروتوكول الإخراج عن المحتوى (تنقية harmony وprotocol_fail موثقان لكل حالة) — إدراج مقارنة QAT مقابل Q4_K_M يُدخل في الدورة الكاملة (gemma-4 لديها QAT رسمي للمقارنة النظيفة).
6. ⬜ توصية نهائية لـD-5 (قرار مالك): نموذج «المهام المنضبطة» + نموذج «المهام العميقة» + احتياطيان — **لا اختيار مسبق**.
