## 2. المعمارية (المنفذة)

```
┌──────────────────────── Alkemos.com (مصدر الحساب — Supabase Auth) ────────────────────────┐
│  دخول المستخدم (بريد/كلمة مرور · Google OAuth) ← الاستعادة وتغيير كلمة المرور هنا وحدها     │
│  الجلسة: رمز وصول (JWT/معتم) في كوكيز · المصدر: auth.users.id (UUID) · الدور: profiles.role │
└──────────────────────────────────┬────────────────────────────────────────────────────────┘
                                   │ (الموقع يمرر رمز جلسة المستخدم جهة الخدمة عند كبلة المحرك — لاحقًا D-17)
                                   ▼
┌──────────────── المحرك: طبقة الهوية الموحدة (engine/identity + adapters/identity) ─────────┐
│  UnifiedIdentityService.authenticate(upstream_token)  ← رمز منبع معتم فقط (نص)            │
│    1) المزود يتحقق جهة الخدمة عند مصدر الحساب:                                             │
│       supabase-introspection (الافتراضي — adapters/identity):                              │
│         GET /auth/v1/userinfo (هوية المستخدم) → GET /rest/v1/profiles (الدور)               │
│         → للمدرب: GET /rest/v1/coach_assignments (النطاق)                                  │
│       jwks (المسار الثاني — تحقق محلي بتوقيع غير متماثل عبر مفاتيح عامة منشورة)            │
│    2) VerifiedAccount {account_id UUID · role · scope · email(عرض فقط) · expires_at}      │
│    3) IdentityResolver يترجم بأقل صلاحية ويسكّ رمز محرك قصير العمر عبر TokenAuthority:      │
│         المالك بمعرف الحساب (ALKEMOS_OWNER_ACCOUNT_IDS) → owner (بمفتاح المالك المستقل)    │
│         admin → أدمن كل الحسابات · coach → أدمن مسنديه (بلا مسندين: عميل لنفسه)            │
│         client → عميل لنفسه · دور مجهول → فشل مغلق                                        │
│    4) AccountIndex (فهرس حسابات — بيانات هوية منفصلة عن بيانات النموذج، مستوى أ)           │
└──────────────────────────────────┬────────────────────────────────────────────────────────┘
                                   ▼
        MemoryService / ConsentLedger / G-EX — بهوية موثقة (Principal) مفتاحها معرف الحساب
```

### 2.1 المكونات

| المكوّن | الموقع | المسؤولية |
|---|---|---|
| `contract.py` | engine/identity | عقد الحساب الموثق `VerifiedAccount` (إنشاء محروس بالإغلاق) · معرف UUID كانوني · أدوار المنبع · مسارات مطالبات محظورة البدء بـuser_metadata |
| `resolver.py` | engine/identity | الترجمة بأقل صلاحية + سقف عمر رمز المحرك بانتهاء جلسة المنبع + جلسة الخدمة (كبلة الموقع) |
| `service.py` | engine/identity | الباب العام `UnifiedIdentityService` (رمز منبع معتم فقط) — لا واجهة مستخدم · بوابة الخدمة تطلب برهان الخادم (مراجعة الدفعة) · **ترتيب العمليات: لا تسجيل ولا أحداث قبل نجاح التحقق الكامل (استكمال المراجعة)** |
| `server_proof.py` (مراجعة الدفعة) | engine/identity | مدقق برهان الخادم لبوابة جلسة الخدمة — حد الثقة بين الموقع والمحرك (تحقق بمفتاح عام مثبت فقط، نقية بلا شبكة) + jti إلزامي يُستهلك بعد نجاح التحقق كله |
| `replay.py` (استكمال المراجعة) | engine/identity | ذاكرة استهلاك براهين الخادم (jti): أحادية الاستخدام، ذرية للخيوط والعمليات (flock + قراءة طازجة)، باقية عبر إعادة التشغيل، محدودة زمنيًا وبسقف صوت عالٍ — نقية بلا شبكة |
| `accounts.py` | engine/identity | فهرس حسابات: بيانات هوية/تفضيلات/استخدام — منفصلة عن بيانات النموذج، مستوى أ |
| `providers/static.py` | engine/identity | مزود محاكاة **للاختبار فقط** (لا يسجل للإنتاج) |
| `supabase_introspection.py` | adapters/identity | مزود مصدر الحساب القائم — **نفس آلية تحقق الموقع** |
| `jwks.py` | adapters/identity | مزود التحقق المحلي بتوقيع غير متماثل (RS256 — رياضي خالص) |
| `__init__.py` (جذر التركيب) | adapters/identity | بناء الخدمة من `engine/settings.py` (متغيرات البيئة) — يرفض مزود المحاكاة |
| `settings.py` (v2) | engine | إعدادات الهوية (مزود/مصدر/مفتاح نشر/معرفات مالك/عمر الرمز) — بلا بريد وبلا أسرار |

**قانونا التوزيع:** (أ) لا أسماء منصات داخل `engine/` — مزود المنصة
المسمى يعيش في `adapters/`؛ (ب) لا استيراد شبكي داخل `engine/` — المزودان
الشبكيان في `adapters/` (يفحصه `test_engine_security.py` §6 آليًا).

### 2.2 لماذا الاستعلام عند المصدر هو الافتراضي (وليس JWKS)

لأنه **نفس آلية الموقع الحالية حرفيًا** (تحقق حي لكل جلسة عند خدمة
المصادقة + الدور من قاعدة البيانات جهة الخدمة) — لا يفترض آلية غير
موجودة. JWKS جاهز ومختبر (بمفاتيح مولدة محليًا) لكن تفعيله يتطلب تفعيل
مفاتيح التوقيع غير المتماثلة في مشروع المنبع (فجوة G-03 — خطوة نشر بيد
المالك لم تتحقق بلا اتصال إنتاجي).

**سياسة مفاتيح RSA (مراجعة الدفعة — أمر المالك):** أي مفتاح JWKS معياره
أقل من **2048 بت** يُرفض عند حلّ المفتاح **قبل التحقق من التوقيع** — فلا
يُستهلك توقيع بمفتاح ضعيف مهما كان الرمز سليم الشكل (مختبر سالبًا:
512/1024/2047 بت كلها مرفوضة عند المفتاح، و2048 يعمل). السياسة نفسها
تنطبق على مفاتيح خادم الموقع لبرهان الخدمة (§3) عند الإعداد.

### 2.3 ما الذي لم يتغير

- `engine/auth.py` (TokenAuthority/Principal/OwnerVerifier) كما هو — طبقة
  رموز المحرك الداخلية؛ الرموز تُسك الآن **بعد تحقق المنبع** عبر المحلل.
- `MemoryService`/`ConsentLedger`/بوابة G-EX — عقودها كما هي؛ الفرق
  الوحيد: `principal_id` صار **معرف الحساب UUID** (لا بريد ولا معرف حر).
- EVO/M2/الحصص/بيانات العملاء: **لم تُلمس** (قيد الدفعة).
- لا واجهة مستخدم، ولا اتصال إنتاجي، ولا مفاتيح تشغيل، ولا قناة بريد.

## 3. حدود الثقة الفعلية (المحدّثة)

| الحد | ما يحمي فعليًا | ما لا يحميه (موثق بصراحة) |
|---|---|---|
| **هوية المستخدم** | نداء جهة الخدمة لمصدر الحساب (userinfo) — المزود يتحقق حيًّا بكل دخول | الرمز المنبع ذاته إن انكشف قبل انتهائه — سقف التخفيف: عمر رمز المحرك ≤ عمر جلسة المنبع، والمصدر يمتلك إبطال الجلسة |
| **الدور** | يقرأ من صف `profiles` جهة الخدمة تحت RLS (نفس مصدر حقيقة الموقع) — لا من الرمز ولا من المستدعي | — |
| **نطاق المدرب** | يقرأ من `coach_assignments` بالرمز نفسه تحت RLS — فشل الجلب = فشل مغلق (لا افتراض) | — |
| **الملكية** | ربط معرف الحساب في `ALKEMOS_OWNER_ACCOUNT_IDS` + توقيع مفتاح المالك المستقل (`attest`) | البريد **لا يمنح شيئًا** (فحص ضد-انحدار: حساب ببريد المالك القديم يبقى عميلًا) |
| **بوابة جلسة الخدمة (مراجعة الدفعة)** | رمز المنبع **+ برهان خادم** معًا: برهان قصير العمر (≤300ث) موقّع RS256 بمفتاح خادم الموقع الخاص ومرتبط برمز الجلسة (بصمة sha256) وحسابه (sub) وجمهور المحرك — التحقق بالمفتاح العام المثبت فقط (`ALKEMOS_SERVICE_CALLER_KEYS` — لا سر مشترك) | امتلاك رمز/جلسة العميل وحده لا يفتح البوابة (مختبر)؛ سرقة مفتاح الخادم الخاص = جلسات خدمة لعملاء أصحاب الجلسات القائمة فقط (نطاق الرمز عميل واحد + سقوف النوع)؛ بلا مفاتيح مثبتة البوابة معطلة كليًا (فشل مغلق) |
| **أحادية برهان الخادم (jti — استكمال المراجعة)** | البرهان يحمل `jti` إلزاميًا (بلا هوية = مرفوض فشلًا مغلقًا)؛ أول تحقق ناجح **يستهلكه** (`engine/identity/replay.py`): ذاكرة ذرية (قفل خيوطي + flock بين العمليات مع قراءة طازجة من الملف داخل القفل — فائز واحد حصرًا تحت التزامن) **باقية عبر إعادة التشغيل** (ملف مستوى أ خارج git — البرهان المستهلك قبل الإقلاع مرفوض بعده) ومحدودة زمنيًا (كل مدخل يسقط بعد انتهاء البرهان + سماحية الساعة) وبسقف حجم رافض صوتًا عالٍ؛ الاستهلاك بعد نجاح التحقق كله فالبراهين الفاسدة لا تحرق هويات سواها؛ الذاكرة مستقلة عن مجموعة المفاتيح فتتدور مفاتيح الموقع دون مسحها | إعادة استخدام برهان ملتقط خلال صلاحيته مرفوضة (مختبر)؛ حذف مقصود لمدخلات الذاكرة من مالك حق الكتابة = مسؤولية تشغيلية معلنة (R-64 — الفساد الصريح صوت عالٍ أما الحذف فمراقبة/صلاحيات/نسخ) وتخفيف بنيوي: البرهان مقيد بالرمز والحساب و≤300ث |
| **ترتيب عمليات البوابة (استكمال المراجعة)** | لا تسجيل في AccountIndex ولا أحداث ولا أي أثر جانبي قبل نجاح التحقق الكامل (المنبع ← البرهان ← سكّ الجلسة **ثم** التسجيل) — الاستدعاء المرفوض لا يترك أثرًا (مختبر) | سلوك `authenticate()` العام محفوظ حرفيًا كما كان (مختبر كتثبيت — أمر المالك) |
| **امتيازات المحرك** | توقيع HMAC لرمز المحرك (مفتاحا المنصة/المالك — خارج المستودع) بعد تحقق المنبع؛ سقف صلاحيات لكل نوع؛ عزل بالنطاق | مهاجم **داخل العملية** يملك `TokenAuthority` (يمكنه سكّ رموز مباشرة) — خارج نموذج التهديد المعلن (عقيدة دفعة 16: الإغلاق حارس صحة لا حد أمني) |
| **الإغلاقات (VerifiedAccount/Principal)** | صناعة محرسة + شهادة كريبتوغرافية (`attest`) | ليست حدًّا أمنيًا ضد مهاجم داخل العملية — الحد هو حيازة المفاتيح |
| **عمر الجلسة** | exp الرمز ≤ exp جلسة المنبع + فحص iat/exp/iss/aud/nbf في JWKS | انحراف الساعة — تخفّف بتسامح ساعة قابل للضبط (60 ث افتراضيًا) |
| **بيانات الهوية** | فهرس مستوى أ خارج شجرة git + تكامل ذاتي + قفل + كتابة ذرية | — |
| **فصل الهوية/النموذج** | ملفات وأدلة مختلفة: `accounts-state.json` مقابل `memory.jsonl` — مفتاح ربط واحد (UUID) | — |

**مسارات الهجوم المختبرة سلبيًا (كلها تفشل):** بريد المستدعي · دور من
المستدعي · عبث حمولة رمز موقّع · رمز منتهٍ/مستقبلي/مصدر غريب/جمهور غريب ·
مفتاح مجهول بعد تدوير · خوارزمية none/HS256/ES256 · sub بريد · حساب بلا
صف دور · فشل جلب النطاق · عميل خارج نطاقه · مدرب خارج مسنديه · أدمن يحاول
الكتابة/الحذف النهائي · انتحال حسابات عبر القواميس · رمز محرك معدّل · **(مراجعة الدفعة)** برهان خادم غائب/بمفتاح غير مثبت/لرمز أو حساب آخر/منتهٍ/فوق سقف العمر/بجمهور غريب · برهان بمفتاح ضعيف (<2048) يرفض عند الإعداد · **رمز JWKS بمفتاح ضعيف يرفض قبل التحقق من التوقيع** · تزوير هوية من بيانات فهرس الحسابات (سجل/أحداث/roles_seen محقونة) · **(استكمال المراجعة)** برهان بلا jti · إعادة استخدام برهان خلال صلاحيته (نفس العملية · عبر إعادة التشغيل · تحت تزامن 8 خيوط و4 عمليات fork) · برهان بعد تدوير صارم للمفاتيح · استدعاء مرفوض يترك أثر فهرس/حدث — كلها تفشل.

## 4. عزل بيانات العملاء (فصل الهوية عن النموذج)

لكل حساب (UUID) — بلا تسجيل منفصل:

| البيانات | مكانها | مفتاحها |
|---|---|---|
| بيانات الهوية (أول ظهور · أدوار مشاهدة · جلسات · تفضيلات) | `AccountIndex` — مستوى أ خارج git | معرف الحساب |
| الذاكرة (حقائق نشطة/ملغاة) | `MemoryStore` — مستوى أ خارج git | `client_id` = معرف الحساب (عبر `Principal`) |
| الموافقات والانسحابات | `ConsentLedger` — مستوى أ خارج git | `client_id` + هوية المسجل الموثقة |
| المحادثات (المستوى ج) | اليوم في موقع Alkemos.com (لم يُنقل) — عند بناء تخزينها في المحرك مفتاحها معرف الحساب نفسه | معرف الحساب (خطة) |
| الاستخدام | عداد جلسات في الفهرس + عداد استخراج الذاكرة لكل حساب | معرف الحساب |

العزل البنيوي مفروض من `Principal.can_access_client` — معرفة معرف حساب
آخر لا تمنح وصولًا (مختبر موجبًا وسالبًا).

### 4-ب. حدود سلامة فهرس الحسابات وسجل أحداثه (مراجعة الدفعة — موثقة بصدق)

| الأصل | ما يكشفه فعلًا | ما لا يكشفه (الحد الصريح) | المرساة/التخفيف |
|---|---|---|---|
| بصمة SHA-256 لحالة الفهرس (`accounts-state.json`) | **التلف العرضي:** انقطاع كتابة، انحراف ملف، تعديل جزئي بلا إعادة حساب — يُعلن بصوت عالٍ (مختبر) | **العبث المتعمد:** من يملك حق الكتابة يعيد كتابة الملف **ويعيد حساب البصمة** فتمرّ — مثبت بالاختبار كحدّ لا كادعاء | طبقة تشغيلية: دليل مملوك خارج git (حارس المسار) + صلاحيات ملفات + نسخ احتياطي |
| سجل أحداث الفهرس (`accounts-events.jsonl`) | الفساد الصريح عند القراءة (سطر JSON غير قابل للقراءة) | **الاقتطاع/الحذف الصامت/إعادة الكتابة** — سجل إلحاقي بلا سلسلة ولا توقيع؛ الشيفرة لا تكشفها إطلاقًا | طبقة تشغيلية نفسها — لا يُستخدم السجل لإثبات أي شيء أمني |
| بيانات الفهرس كلها (سجلات · roles_seen · عدادات · تفضيلات) | بيانات خدمية/أرشيفية للعرض | **ليست مصدر إثبات هوية أو صلاحيات أبدًا** — مهما حُقنت من حقول (مختبر سالبًا: تزوير roles_seen بإعادة حساب البصمة لا يغير هوية الجلسة؛ السجلات والأحداث لا تصلح هوية) | الهوية الحية من تحقق المزود من المنبع حصرًا؛ الصلاحيات من سكّ TokenAuthority عبر المحلل بأقل صلاحية |

**القاعدة الحاكمة:** SHA-256 في طبقة الفهرس = **كشف تلف، لا منع عبث** —
أي ادعاء أقوى يُرفض في التوثيق والكود معًا (موثق كذلك في
`engine/identity/accounts.py`).

## 5. تبديل مزود الهوية (العقد)

تبديل المزود = ضبط `ALKEMOS_IDENTITY_PROVIDER` (+ إعدادات المزود) — لا
تغيير في أي مستهلك:

- `supabase-introspection` (الافتراضي): `ALKEMOS_IDENTITY_ISSUER` +
  `ALKEMOS_IDENTITY_ANON_KEY` (مفتاح النشر العام — **ليس سرًّا**).
- `jwks`: `ALKEMOS_IDENTITY_JWKS_URL` + `ALKEMOS_IDENTITY_ISSUER` +
  اختياريًا `ALKEMOS_IDENTITY_AUDIENCE` و
  `ALKEMOS_IDENTITY_ROLE_CLAIM_PATH` (مطالبة متحكم بها جهة الخدمة مثل
  `app_metadata,engine_role` — المسارات المبدوءة بـ`user_metadata`
  **ترفض من البناء**).
- `static-test`: **يرفضه جذر التركيب** (محاكاة اختبارية فقط).

مزوّد مستقبلي (مثال IdP آخر لوغير Supabase) = تنفيذ
`verify_upstream_token → VerifiedAccount` واحد في adapters/ + سطر في
السجل — المستهلكون والمحلل والفهرس كما هم.

## 6. واجهة AlkemosAI المستقلة المستقبلية (خطة — لا تنفيذ الآن)

بقرار المالك: **لا تُنشأ أي واجهة في هذه الدفعة.** الخطة الموثقة:

1. **الدخول/التسجيل:** الواجهة تواجه مصدر الحساب نفسه (Supabase Auth)
   — نفس حسابات Alkemos.com بلا تسجيل منفصل (المستخدم الجديد في أي واجهة
   = حساب Alkemos واحد).
2. **الاستخدام:** خادم الواجهة يمرر رمز جلسة المستخدم إلى
   `UnifiedIdentityService.authenticate/authenticate_service` — نفس
   العقود المنفذة اليوم (قواميس JSON-قابلة-للتمثيل جاهزة للمحول).
3. **إدارة الحساب:** كلمة المرور/الاستعادة/البريد في مصدر الحساب (هي
   مسؤوليته أصلًا)؛ التفضيلات داخل المحرك عبر `AccountIndex`.
4. **الجلسة الموحدة:** رمز المحرك ≤ عمر جلسة المنبع — انتهاء جلسة
   Alkemos.com = انتهاء جلسة AlkemosAI تلقائيًا.
5. لا حاجة لأي تعديل معماري عندئذ — العقد يغطي الواجهتين (الموقع الحالي
   والمستقبلية) بمسار واحد.

## 7. متغيرات البيئة (كلها إعدادات لا أسرار — SECURITY §1)

| المتغير | المزود | ملاحظة |
|---|---|---|
| `ALKEMOS_IDENTITY_PROVIDER` | الكل | الافتراضي `supabase-introspection` |
| `ALKEMOS_IDENTITY_ISSUER` | introspection (إلزامي) / jwks (iss) | رابط HTTPS لمشروع Supabase |
| `ALKEMOS_IDENTITY_ANON_KEY` | introspection | **مفتاح نشر عام معلَن — ليس سرًّا** |
| `ALKEMOS_IDENTITY_JWKS_URL` | jwks (إلزامي) | مفاتيح عامة منشورة |
| `ALKEMOS_IDENTITY_AUDIENCE` / `ALKEMOS_IDENTITY_ROLE_CLAIM_PATH` / `ALKEMOS_IDENTITY_SCOPE_CLAIM_PATH` | jwks (اختياري) | مطالبات متحكم بها جهة الخدمة حصرًا |
| `ALKEMOS_IDENTITY_HTTP_TIMEOUT_SECONDS` | الشبكيان | افتراضي 10 (فشل المهلة فشل مغلق) |
| `ALKEMOS_IDENTITY_ENGINE_TOKEN_TTL_SECONDS` | الكل | افتراضي 12 ساعة — يُسقف دائمًا بعمر جلسة المنبع |
| `ALKEMOS_OWNER_ACCOUNT_IDS` | المحلل | **معرفات حسابات المالك UUID** — القائمة الفارغة = لا عمليات ملكية (فشل مغلق) |
| `ALKEMOS_SERVICE_CALLER_KEYS` (مراجعة الدفعة) | بوابة الخدمة | مفاتيح خادم الموقع **العامة** لبرهان الخادم (`kid:n_hex:e_hex` مفصولة بفواصل — ليست أسرارًا)؛ غيابها = بوابة جلسة الخدمة معطلة كليًا (فشل مغلق) |
| `ALKEMOS_SERVICE_PROOF_REPLAY_ROOT` (استكمال المراجعة) | بوابة الخدمة | مسار **مطلق خارج شجرة git** (مستوى أ) لذاكرة استهلاك البراهين (jti) — **إلزامي عند تفعيل المفاتيح** (جذر التركيب يرفض البناء بدونه بصوت عالٍ): بلا ذاكرة باقية عبر إعادة التشغيل تنفتح نافذة إعادة استخدام عند كل إقلاع |
| `ALKEMOS_MEMORY_AUTH_KEY` / `ALKEMOS_MEMORY_OWNER_KEY` | TokenAuthority | مفاتيح المحرك (كما كانت دفعة 16) — لا تشارك الموقع |
