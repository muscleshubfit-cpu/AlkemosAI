# المرحلة 4 — المعمارية التقنية (تصميم v0.1)

> إصدار: v0.1 · تاريخ: 2026-11-21 · **الحالة: 🟡 تصميم أولي للاعتماد عند G2** · التبعيات: 1 🟡 + 2 🟡 + 3 🟡 (يُعتمد نهائيًا بعدها)

## 1. الهدف

تصميم المحرك المركزي: واجهة موحدة للنماذج، توجيه مهام، إدارة سياق وذاكرة، RAG، أدوات بحث وتحقق، مهام خلفية، مراقبة وحصص وتكاليف، وتبديل/تراجع — بحيث يخدم Alkemos وEVO وأي منتج لاحق دون إعادة كتابة.

## 2. المبادئ المعمارية (مستمدة من خط الأساس)

1. **محرك واحد، مزودون كثراء قابلون للاستبدال** — عقد «لا نقل استدعاء خارج الموجّه» موروث من توحيد Alkemos.
2. **التراجع بمتغير واحد** — كل قرار توجيه مركزي له وضع legacy مجمد (نمط `AI_ROUTER_MODE` المجرّب إنتاجيًا).
3. **الواجهة أولاً:** عقد API ثابت أمام المنتجات (متوافق OpenAI — ADR-0005) بحيث يكون تبديل النموذج شفافًا تمامًا للمستهلك.
4. **الملكية أولًا:** كل حالة خارج النماذج (ذاكرة/معرفة/سجلات) في مخازن نملكها بصيغ قابلة للتصدير.
5. **العدّ لا يعطل التوليد** (fail-open) — موروث.
6. **البوابات الحتمية قبل AI وبعده** — الأرقام تحسب ببرمجيات، وAI يلتزمها (نمط الخطط الموروث).
7. **أصغر محرك يعمل:** MVP لكل طبقة قبل التوسع (ضد R-11).

## 4. عقد الواجهة الموحدة (مسودة — تُثبت عند G2)

- `POST /v1/chat/completions` متوافق OpenAI + امتداد رأس `X-Alkemos-Task` (يحل محل الهاردكود) + استجابة تحمل `{provider, model, qualityTier, cost}` كـ metadata.
- `POST /v1/embeddings` للتضمين (نموذج تضمين متعدد اللغات نملك تشغيله).
- نقطة `/v1/tasks` للمهام الخلفية (عقد طابور مستوحى من ai_jobs مع CAS + idempotency).
- **هدف التكامل:** استهلاك Alkemos يتغير بتغيير base_url + مفتاح فقط (المرحلة 8).

## 5. المهام التفصيلية

1. ✅ تصميم v0.1 (هذه الوثيقة) للمصادقة المبدئية.
2. ⬜ اعتماد G2 → تفصيل العقود (OpenAPI spec) + مخطط مخازن (Postgres + تخزين كائنات S3-compatible).
3. ⬜ بناء MVP بالترتيب: مُهايئ vLLM ← موجّه مصغر ← بوابة + حصص ← عدادات ← RAG نواة ← ذاكرة ← إصلاح موجه.
4. ⬜ كاناري ذهبية (تثبيت سلوك) قبل/بعد كل تغيير — النمط الموروث.
5. ⬜ اختبار تبديل النموذج: نفس الطلبات عبر نموذجين مع الحفاظ على الذاكرة والمعرفة (عمود الملكية 9).
6. ⬜ خطة استمرارية: تدهور رشيق (خارجي عند سقوط الذاتي والعكس — بنمط السلاسل الموروث).

## 6. معايير النجاح

- وثيقة معتمدة G2 + OpenAPI منشورة داخل المستودع.
- MVP يخدم 3 مهام (محادثة/خطة غذائية/خطة تدريبية) عبر نقطة واحدة مع تبديل نموذج بلا انقطاع.
- اختبار «فقد مزود»: سقوط النقطة الذاتية يحول للمخزن الاحتياطي الخارجي خلال ثوانٍ (عداد + سجل).

## 7. المخاطر

R-11 (تضخم التصميم) · تعقيد التوافق المزدوج ذاتي/خارجي (تخفيف: مُهايئ واحد لكل نمط، بروتوكول داخلي واحد).
