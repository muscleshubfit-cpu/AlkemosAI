## 1. منهجية البحث والمصداقية (ملزمة في كل مرحلة)

1. **البحث فعلي على الإنترنت** — لا اعتماد على الذاكرة النموذجية في أي رقم أو سعر أو إصدار أو ترخيص.
2. المصادر المعتمدة: الوثائق الرسمية، مستودعات النماذج (ملفات LICENSE الفعلية لا وصفها)، صفحات الأسعار الرسمية، الاختبارات المستقلة. **لا دعاية تسويقية.**
3. كل مصدر يوثق في `references/sources-log.md` بـ: الرابط + **تاريخ الاطلاع** + ما يؤكده.
4. **الفصل الصارم بين:** [مُقيس] (قياس من كود/سوق/API) / [موثق] (مستندات المشروع) / [تقدير] (حساب استنتاجي) / [غير متحقق].
5. ممنوع اختراع أسعار أو مواصفات أو نتائج اختبارات — ما لم يُعثر عليه يُكتب صراحة «غير متحقق حتى 2026-11-21».
6. «مفتوح الأوزان» ≠ «مملوك قانونيًا بالكامل»: يفحص كل ترخيص من مصدره للاستخدام التجاري + التعديل + التدريب على المخرجات + التقطير.
7. المعلومات غير المتحقق منها تُذكر باسمها في وثيقة المرحلة تحت قسم «ما لم يُتحقق بعد».

4. اللغة: عربية أساسًا بمصطلحات تقنية إنجليزية معيارية (قرار ADR-0003). README فقط ثنائي اللغة كاملًا.
5. تسمية الملفات: `phase-NN-<slug>.md` داخل مجلد المرحلة، أو `aws-audit.md` / `initial-screening.md` للوثائق الخاصة.

## 4. بروتوكول العمل والدفع

1. قبل أي جلسة: قراءة `STATE.md` ← ملف المرحلة ← هذا الملف.
2. قبل أي ادعاء عن المستودع المرجعي: `git fetch` والتحقق من HEAD (لا ذاكرة محادثة).
3. بعد كل دفعة إنجاز: مراجعة اتساق النتائج ← تسجيل القرارات (ADR عند الجوهرية) ← تحديث `STATE.md` وملف المرحلة (حالة التنفيذ) ← commit برسالة وصفية ← push إلى `main` (forward-only، لا force).
4. رسالة الالتزام تصف ما أُنجز فعلًا لا ما هو مخطط.
5. «دفعة واحدة = كوميت واحد = تحديث حالة» — انسجامًا مع قانون المرجع.
