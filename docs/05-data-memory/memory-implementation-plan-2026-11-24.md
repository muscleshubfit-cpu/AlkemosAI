# الخطة التنفيذية: طبقة الذاكرة والمعرفة المستقلة عن النموذج والاستضافة

> التاريخ: **2026-11-24 (UTC)** · النوع: **خطة تصميم — لا تنفيذ**
> هذه الوثيقة لا تبدأ أي بند تنفيذ قبل مراجعة المالك وموافقته الموثقة (قانون البوابات). ولا تمس EVO بأي شكل: لا كود، لا بيانات، لا ميجريشن، لا دورات، لا حصص.
> العلاقة بالمقارنة المقررة: **صفر تأخير** — كل ما هنا وثائق وتصميم؛ قياس M2 (فئة 20B+ على Kaggle بعد التجديد — ADR-0022/قرار D-5) يسير بجدوله كما هو.

---

## 1. المبدأ الحاكم

طبقة الذاكرة والمعرفة **أصل مستقل** يخدم أي نموذج يُختار بعد D-5 وعلى أي استضافة (AWS، تشغيل محلي، Kaggle زمني، أي مزود مستقبلًا): العقد واجهات، التخزين ملفات مفتوحة + قاعدة بيانات مملوكة، والفهرس مشتق دائمًا قابل لإعادة البناء (ADR-0009). لا يحمل الملف ولا الجدول ولا الواجهة أي اسم نموذج أو مزود أو منصة استضافة.

---

## 2. البنية: ثلاثة مستويات منفصلة إلزاميًا + فهرس مشتق

### المستوى A — ذاكرة العملاء (خاص، يحمل هوية)
- **النمط:** `evo_memory`/0078 — حقائق دائمة بصيغة الغائب ≤300 حرف، فئات ثابتة، ثقة، `is_active`، استخراج كل N رسالة، عداد على الخادم فقط.
- **قائمة الحرمان داخل عقد الاستخراج:** لا تشخيصات، لا أدوية، لا صحة نفسية، لا تفاصيل سريرية دقيقة، لا اتصال، لا مالية، لا أسماء أشخاص آخرين.
- **التخزين:** Postgres مملوك + تصدير JSONL؛ **خارج المستودع العام نهائيًا**.
- **الحوكمة:** المالك يقرأ/يصحح/يعطل؛ الإلغاء بدل الحذف؛ الحذف النهائي بأمر مالك موثق فقط (نمط D2).
- **حد التدريب:** لا يدخل أي تدريب إلا بعد تجريد هوية كامل + موافقة مالك مستقلة موثقة (R-07).

### المستوى ب — المعرفة العامة مجهولة الهوية (داخل المستودع)
- بطاقات G-K القائمة (`memory/cards`) + أنماط التجميع المجهولة بنمط E1/E2/E3 (أرقام ولهجة أطباق وأسعار، بلا أسماء أشخاص ولا نص حر من الخطط — الاستخلاص من الحقول المنظمة فقط).
- **أرضية الصدق:** `sample_size ≥ 3` لكل تجميع — العينة الرقيقة تُحجب أو تُسمّى، لا تُقدَّم كمعرفة.
- الفهرس المتجه مشتق من الملفات دائمًا: تغيير نموذج التضمين = إعادة فهرسة بأمر واحد، لا هجرة بيانات (ADR-0009).
- قاعدة المعرفة العلمية (phase-05 §2: WHO/ACSM/AND/CDC/NHS + PubMed/Cochrane) تدخل هنا عبر G-K نفسها مع استشهاد إلزامي.

### المستوى ج — سجل المحادثات والخطط (إضفوري، مصدر مرشّحات فقط)
- رسائل المحادثة، الخطط المولدة، تعديلات واستبدالات الأعضاء، التغذية الراجعة — append-only، احتفاظ بحد زمني موثق، وصول service-role/أدمن فقط (نمط 0077/0081).
- **وظيفته الوحيدة:** توليد مرشّح أمثلة يمر ببوابة G-EX — لا يُحقن خامًا في أي برومت أبدًا، ولا ينتقل إلى ب إلا بعد التجريد والبوابة.
- الفصل صارم: A يقرأ من ج فقط عبر استعلام الحقن الرسمي؛ ب لا يلتقي بج إلا خلف G-EX.

### الفهرس المشتق
فهرسة هجينة (BM25 + متجهات بتضمين مملوك متعدد اللغات) فوق المستوى ب — تُعاد بناءها من الملفات بأمر واحد، واختبارها ضمن بطارية المرحلة 7.

## 3. عقد الواجهة (مستقل عن النموذج والاستضافة)

| الواجهة | المسؤولية |
|---|---|
| `MemoryProvider.getInjectableContext(client_id)` | كتل برومت جاهزة (ذاكرة العميل + قياساته) ناتجة عن دوال نقية — نفس توقيع `formatEvoMemoryForPrompt` |
| `KnowledgeRetriever.search(query)` | مقتطفات معرفة من المستوى ب + KB، كل مقتطف بمصدره وتاريخ مراجعته (إلزام الاستشهاد ضد الهلوسة R-09) |
| `ExampleGateway.submit/approve/reject` | دورة مرشّحات التدريب عبر G-EX |
| `Exporter.exportAll()` | تصدير كامل بصيغ مفتوحة (JSONL + Markdown + SQL) — اختبار استيراد في بيئة نظيفة خلال ساعة |
| `EngineAdapter.run()` | الغلاف الوحيد الذي يعرف هوية المحرك — استبداله لا يلمس أي طبقة أعلاه |

أي محرك (نموذج ذاتي على خادم المالك، محلي، مستضاف) يستهلك العقد نفسه؛ **تغيير النموذج = استبدال adapter واحد**، والذاكرة والمعرفة والسجلات كما هي.

## 4. دورة التعلم التراكمي (7 خطوات مغلقة)

1. **التقاط يومي:** مراقب المصدر الأساسي C1 (القائمة البيضاء D-15 — تظل جداول التغذية نافذة رغم تأجيل blog_posts) + تدفق التغذية الراجعة + أحداث تعديل الخطط → `memory/inbox`.
2. **تجميع أسبوعي حتمي بلا LLM (تكلفة صفر):** نمط E1 (حذف العائلة وإدراج نظيف) + استخلاص exemplar بنمط E2 (حقول منظمة فقط) + إشارات الاستبدال بنمط E3 (فرق المحتوى + أرضية 3).
3. **توليد المرشّحين:** بطاقات معرفة → G-K؛ أمثلة تدريب → G-EX؛ مهارات → G-S.
4. **البوابات:** كل بوابة بفحوص طفرة إلزامية (نمط 26/26) وتوقيع UTC.
5. **اعتماد المالك:** كل قبول أو رفض بقيد في `learning-log` بالصيغة الإلزامية القائمة — «ضمير التراكم» يُحدَّث في نفس الدفعة.
6. **التبنّي:** بطاقات المستوى ب + مجموعات `datasets/approved/` بإصدار وبصمة sha256 وأصل كامل.
7. **القياس والتغذية العكسية:** منحنى جودة أسبوعي بنمط `evo_eval_runs` قبل/بعد كل تغيير معرفة — نتائجه تعود خطوة 1 (تقاط اليومي).

القاعدة الواضحة: في هذه الطبقة الأوزان مجمّدة — التعلم كله استرجاع وتجميع واعتماد؛ والتدريب المستقبلي (متعدد الدورات، بيئات متقطعة ADR-0010) يستهلك **فقط** ما عبر G-EX.

## 5. ضوابط جودة البيانات والخصوصية

1. أرضية الصدق في كل تجميع (`sample_size ≥ 3`)، وسقوف مقصوصة (نمط EVO_AGG_SOURCES_MAX=500، EVO_SWAP_DIFF_MAX=40) حتى لا يغرق حدث صاخب الدورة.
2. التجريد قبل أي خروج من المستوى ج: إزالة المعرفات، تجميع، فحص آلي لقائمة الحرمان + عينة مراجعة بشرية دورية.
3. الاحتفاظ: سجل المحادثات بحد زمني موثق؛ ذاكرة العميل إلغاء تنشيط لا حذف؛ الحذف النهائي بأمر مالك موثق فقط.
4. الوصول: الكتابة service-role فقط، RLS صارم بلا سياسات عميل على الجداول التشغيلية (نمط 0078/0080/0081)، وقراءة الأدمن للمراجعة فقط.
5. UTC موحد للطوابع (ADR-0013)؛ القيود المقفلة لا تُعدل — التصحيح بقيد لاحق يحيل إليه (نمط learning-log).
6. فحص ثنائي اللغة AR/EN في كل بوابة (قاعدة G-K القائمة).
7. لا أسرار ولا مفاتيح في أي وثيقة أو بطاقة أو مجموعة بيانات (SECURITY §7 / R-32 — وتشمل توصية تدوير أي مفتاح شُرح نصًا في محادثة وكلاء).

## 6. بوابة اعتماد الأمثلة قبل التدريب (G-EX — مقترح جديد)

الشروط الخمسة، كلها فحوص آلية + توقيع مالك، ولا مثال يعبر إلا باكتمالها:

1. **أصل موثق:** ملف مصدر + SHA مطابق حرفيًا + تاريخ اطلاع صالح تقويميًا (نفس فحوص G-K المشددة في LEARN-002/003).
2. **تجريد هوية مكتمل:** قائمة الحرمان + فحص آلي + عينة بشرية؛ أي شك = رفض مؤرشف.
3. **جودة المصدر:** تغذية راجعة إيجابية أو اجتياز بوابات السلامة/التقييم (نمط `safety_pass` + قاضٍ 0–10).
4. **لا تعارض:** مع بطاقات المستوى ب المعتمدة (نمط ADR-0017 — لا كتابة صامتة فوق معرفة قائمة).
5. **تصنيف استخدام:** `تدريب فقط` / `تدريب+استرجاع` / `استرجاع فقط` — بقيد استخدام واحد لا يُعدل.

**المخرجات:** المقبول → `datasets/approved/EX-xxxx` بإصدار وبصمة وأصل كامل + قيد في learning-log. المرفوض → `memory/archive` بسببه الموثق — لا حذف أبدًا.

## 7. كيف تُستفاد من الطبقة مع أي نموذج لاحقًا (بلا ربط بنموذج)

- **قبل D-5:** كل ما يُبنى لا يعتمد على هوية النموذج — يعتمد على العقد في §3 فقط؛ وبالتالي لا يتأخر بأي نتائج مقارنة.
- **بعد D-5:** يُكتب `EngineAdapter` واحد للمحرك المختار (ذاتي/محلي/مستضاف) يحقن نفس كتل الذاكرة والمعرفة ويستدعي نفس المسترجع.
- **اختبار التبديل (معيار الاستقلالية):** تشغيل بطارية M2 نفسها على محركين مختلفين فوق الطبقة نفسها **بلا تغيير واحد في البيانات** — واجتيازه شرط لقبول أي بناء لاحق.
- **وصفة التصدير:** `export --all` ثم استيراد في بيئة نظيفة خلال ساعة — الدليل العملي على أن الطبقة أصل مملوك قابل للنقل (phase-05 م5-4).

## 8. الجدول الزمني المرتبط بمراحل الخطة القائمة (بلا تأخير للمقارنة)

| النافذة | ما يحدث | ما لا يحدث |
|---|---|---|
| الآن حتى 2026-11-28 | هذه الوثائق الثلاث فقط (تدقيق/خريطة/خطة) | لا كود، لا Kaggle، لا مساس بM2 |
| بعد نتائج M2 وقرار D-5 | M4-ذاكرة-1: بناء R1 + نقل الوحدات النقية + اختباراتها (دفعة قصيرة واحدة) | لا تدريب، لا وضع ظل |
| بالتوازي مع M4/M5 | دورة التجميع الأسبوعية + بوابة G-EX + أول 20 مثالًا معتمدًا + منحنى الجودة التشغيلي | لا توجيه أي مهمة إنتاجية |
| قبل المرحلة 8-ب (وضع الظل) | جاهزية المنحنى التشغيلي + وصفة التصدير المجربة | لا استدعاء حي للمحرك الجديد |

## 9. الحدود الصارمة (إلزامية)

1. EVO: قراءة فقط — لا كود ولا بيانات ولا ميجريشن ولا دورات ولا حصص، والإنتاج كما هو حرفيًا.
2. لا نسخ قاعدة بيانات: القراءة عبر واجهات المصدر الأساسي وحصرًا للقائمة البيضاء بلا PII (D-15 + phase-05 م5-6).
3. لا خدمات مدفوعة، ولا مزود تضمين رابع خارج القائمة، ولا تدريب قبل اعتماد مجموعات G-EX بقرار مالك.
4. لا تنفيذ قبل مراجعة هذه الخطة وموافقة المالك الموثقة — والموافقة تفتح «M4-ذاكرة-1» فقط.

## 10. معايير النجاح

- 100% من كتل الحقن ناتجة عن دوال نقية مُختبَرة (نمط اختبارات evo-memory، وفحوص طفرة ≥20 لكل بوابة).
- اجتياز اختبار التبديل بين محركين على الطبقة نفسها بلا تغيير بيانات.
- اجتياز اختبار التصدير/الاستيراد خلال ساعة.
- صفر PII في المستوى ب ومجموعات G-EX (فحص آلي + عينة بشرية دورية).
- سجل التعلم محدث بكل قرار — قبولًا ورفضًا — في نفس الدفعة.

## 11. المخاطر والتخفيف

| الخطر | التخفيف |
|---|---|
| ربط ضمني بنموذج أو مزود | العقد الواجهي + اختبار التبديل الإلزامي |
| تضخم مرشّحات غير مراجعة | سقوف التقاط اليومي + بوابة G-EX + أرشفة الرفض |
