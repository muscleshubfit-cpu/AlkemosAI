# دراسة الموارد الحاسوبية المجانية — التقييم الآن وQLoRA لاحقًا (دفعة 13-ب — 2026-11-22/23 UTC)

## 2. ملاءمة Kaggle لتقييم المرشحين (M2 — الآن)

### 2.1 أرقامنا المقاسة فعلًا (المرجع الوحيد المتاح قبل GPU)

| القناة | النموذج | متوسط زمن الحالة (عينة 36) | إسقاط 162 كاملة |
|---|---|---|---|
| GHA CPU (قناتنا الحالية) | Qwen3.5-9B Q4_K_M | 36.2 ث | ~1.6 ساعة |
| GHA CPU | Ornith-1.5-9B | 79.8 ث | ~3.6 ساعة |
| GHA CPU | gemma-4-12b | 106.2 ث | ~4.8 ساعة |
| GHA CPU | gpt-oss-20b MXFP4 | 28.3 ث | ~1.3 ساعة |
| قناة GLM المجانية (API) | glm-4-plus | **4.1 ث** | **~11 دقيقة** |

- **الخلاصة العملية:** S/M (حتى 12B) يُقاس على GHA CPU مجانًا بلا ضغط — والبطارية الكاملة لنموذج واحد تستهلك 1.3–4.8 ساعات GHA (لا تحسب من حصة GPU إطلاقًا).
- **Kaggle GPU يصبح ضروريًا فقط لـ:** 20B+ (27B/32B/35B-A3B) — على T4×2 عبر llama.cpp بتمرير `--tensor-split` أو vLLM المكمّم: تقديريًا 5–15× أسرع من CPU أي بطارية 162 كاملة في ~20–40 دقيقة نموذجًا. [تقدير موثق — يُقاس فعليًا أول جلسة]
- **خط الحصة:** 30 س/أسبوع تكفي نظريًا ~15–20 بطارية كاملة للفئة 20B+، أو جولتي QLoRA صغيرتين (§3) — **التقييم والضبط يتنافسان على نفس الحصة** — يلزم جدولة موسمية (تقييم M2 أولًا ثم تحويل الحصة لـM3 بعد D-5).

## 3. ملاءمة Kaggle لـQLoRA/Unsloth مستقبلًا (M3/M4 — بعد D-5 حصرًا)

| حجم النموذج الأساس | QLoRA 4-bit على T4 واحدة (15GB) | على T4×2 | ملاحظات |
|---|---|---|---|
| ≤4B | ✓ مريح (1B<4GB · 3B≈7GB — Unsloth) | ✓ | تدريب سريع، جولات كثيرة |
| 7–9B | ✓ (حالة Unsloth القياسية على T4) | ✓ | **النطاق الأمثل لحصتنا** |
| 12–14B | ⚠️ ضيق (باتش صغير + سياق 2048) | ✓ أفضل | ممكن بضبط دقيق |
| 27–32B | ✗ على واحدة | ⚠️ على الحافة (offload + بتش صغير) | بطيء؛ عملي فقط لجولات قصيرة |
| 35B+ كثيفة | ✗ | ✗ | خارج المجاني — باب D-13 فقط |

- **Unsloth يدعم رسميًا** (وثائقه، اطلاع 2026-11-22): Qwen3.5 · Qwen3.6 · Qwen3.8-27B · Gemma 4 · GLM-5.3-Flash · DeepSeek V4.x · Kimi K3 · Nemotron 3.5 — أي أن كل مرشحينا في نطاق 4–14B مغطاة أدواتيًا على Kaggle. [موثق]
- **حصة أسبوعية كتقدير تدريبي:** دورة QLoRA كاملة لنموذج 9B على بياناتنا (13,432 سجلًا، عصر واحد، سياق 2048) ≈ **4–8 ساعات T4** [تقدير] — أي 3–6 دورات أسبوعيًا نظريًا؛ عمليًا 2–4 مع التقييم والفحص. **لا تدريب يبدأ قبل M3/D-5 — هذا تخطيط سعة فقط.**

## 5. مخاطر وضوابط

- **R-41 (جديد — يقترح إضافته للسجل):** تنافس التقييم والضبط على حصة Kaggle نفسها (30س) — تخفيفه: جدولة موسمية (M2 أولًا) + بروتوكول checkpoint/resume (متوفر) + GHA للفئة الصغيرة.
- **تقلب الحصص بلا SLA** (موثق دفعة 5): القياس الحي قبل كل اعتماد جلسة + إعادة الجدولة الأسبوعية.
- **انقطاع الجلسة (12س):** العدّاء يدعم `--resume` + حفظ تدريجي — يلزم إضافته لأي سكربت تدريب مستقبلي (M3).
- **عدم ضمان T4×2 تحديدًا** (قد تُخصص P100 مفردة): قياس `nvidia-smi` أول الجلسة وتوثيقه في نتيجة التشغيل.
