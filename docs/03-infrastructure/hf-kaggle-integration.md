# تكامل Hugging Face وKaggle — التفعيل والتحقق الفعلي (دفعة 10 — ADR-0020)

> **تاريخ التنفيذ:** 2026-11-22 (UTC) · **القرار:** [ADR-0020](../../decisions/ADR/ADR-0020-hf-kaggle-accounts-activation.md) · **النطاق:** جاهزية بنية تحتية بلا تدريب ولا توليد ولا أي استهلاك موارد — ضمن D-11 (مجاني/CPU حصرًا).
> **قانون الأسرار:** لا قيمة سرية في هذه الوثيقة ولا في أي ملف — الأسماء والحصص ونقاط النهاية فقط (SECURITY §1/§7).

## 1. لماذا هذان المزودان (الأدوار في البنية الحالية)

البنية حددت أدوارهما قبل التفعيل بلا قرار جديد:

| المزود | الدور المعتمد سابقًا | المرجع |
|---|---|---|
| Hugging Face | مستودع Hub **خاص** للتخزين الأول للأوزان (الساق 1 من ثلاثية النسخ) + قناة تنزيل الأساس العام (Apache-2.0/MIT) + موفرو الاستدلال لفحوص الدخان فقط | ADR-0009 · ADR-0011 · ZERO_COST_PLAN §3.1 |
| Kaggle | **بيئة التدريب الأساسية**: 30 GPU-س/أسبوع بجلسات متقطعة قابلة للاستئناف (نقاط حفظ) | ADR-0010 · ZERO_COST_PLAN §4.3 |

القيد النافذ: **لا تدريب أوزان قبل استكمال M1 وقياس M2 (D-5)** — هذه الدفعة جاهزية فقط.

## 2. الحسابات والأسرار (ما هو أين)

| العنصر | القيمة غير السرية | مكان السر |
|---|---|---|
| حساب HF | `Alkemos` (توكن fine-grained: نطاقات `repo.write` + `inference.*` + `user.billing.read` — 18 نطاقًا) | GitHub Secret: `HF_TOKEN` |
| حساب Kaggle | `AlkemosAI` (الاسم الكنسي للمستخدم في الاستعلام: `alkemosai`) | GitHub Secrets: `KAGGLE_USERNAME` · `KAGGLE_KEY` |
| مستودع أوزان HF | `Alkemos/alkemosai-weights` — **خاص فعلًا** | لا سر فيه — التوثيق عام في README خاص |

- الأسرار أُضيفت عبر REST API بتشفير libsodium (ختم مغلق بمفتاح المستودع) — استجابة 201 لكل واحد، والسرد يؤكد وجود الأسماء الثلاثة (GitHub لا تُرجع القيم أبدًا).
- القاعدة الدائمة (SECURITY §7): أُشركت المفاتيح في محادثات وكلاء فتدويرها بعد اكتمال الحاجة إليها بيد المالك لدى مزوديها — وتُحدَّث قيم Secrets بنفس المسار.
- **لا مفتاح في أي ملف أو كود** — سكربت الفحص يقرأ من متغيرات البيئة فقط، والسجلات أثبتت التمويه الكامل (`***`).

## 3. التحقق الفعلي (كله 2026-11-22 UTC)

### 3.1 قياسات Hugging Face

| الفحص | نقطة النهاية | النتيجة المقيسة |
|---|---|---|
| HF-1 صلاحية التوكن | `GET huggingface.co/api/whoami-v2` (Bearer) | 200 — الحساب `Alkemos`، توكن fine-grained بنطاق repo.write ✓ |
| HF-2 مستودع الأوزان | `GET huggingface.co/api/models/Alkemos/alkemosai-weights` | موجود + `private: true` (بلا مصادقة = 401) — رأس الالتزام `42c081f` |
| HF-2 إنشاء ورفع (إثبات الكتابة) | `create_repo` + `upload_file` (huggingface_hub الرسمي) | أُنشئ خاصًا ورُفع README دوره — **لا أوزان فيه** (M2 لم تبدأ) |
| HF-3 راوتر الاستدلال | `GET router.huggingface.co/v1/models` (Bearer) | 200 — **158 نموذجًا مسرودًا بلا أي توليد** (سرد لا يستهلك رصيدًا) |

### 3.2 قياسات Kaggle

| الفحص | نقطة النهاية | النتيجة المقيسة |
|---|---|---|
| KG-1 صلاحية المفتاح | `POST api.kaggle.com/v1/security.OAuthService/IntrospectToken` (Basic) | 200 — `active: true` · المستخدم `alkemosai` · النطاق `resources.admin:*` (مفتاح خاطئ = 404) |
| KG-2 خدمة kernels + الحصة | `POST api.kaggle.com/v1/kernels.KernelsApiService/GetAcceleratorQuotaStatistics` (**Bearer**) | 200 — GPU: **0 ساعة مستخدمة من 30 س/أسبوع** · TPU: 0 من **20 س/أسبوع** · التجديد `2026-11-28T00:00:00Z` |

**قراءة الحصة كانت قراءة-فقط — لم تُستهلك ثانية GPU واحدة ولا أُنشئ أي kernel.**

### 3.3 نموذج مصادقة Kaggle المكتشف (مهم لسكربتات M2)

اكتشاف مقيس يحكم كل أتمتة تدريب قادمة:

1. خدمة **datasets** تقبل HTTP Basic (اسم المستخدم + KGAT).
2. خدمة **kernels** (التدريب والحصص) **ترفض Basic (401 UNAUTHENTICATED) وتقبل `Authorization: Bearer <KGAT>`**.
3. **سرد البيانات العامة بلا اعتماديات يعيد 200** (مثلًا `ListDatasets`) — أي أن «200» وحده لا يثبت صلاحية مفتاح؛ الإثبات القاطع وحده `IntrospectToken` (مفتاح خاطئ = 404).
4. CLI الرسمي (kaggle 2.2.5): يصادق محليًا بمفتاح legacy من `~/.kaggle/kaggle.json` لكن بيئة Actions لا تحتاجه — السكربت يستدعي النقاط مباشرة.

### 3.4 التحقق داخل GitHub Actions (البيئة المرجعية)

- **التشغيل:** `45028375241` على الالتزام `26cfea3` (بدأ `2026-11-22T13:36:29Z` — نجح).
- **النتيجة الفعلية من سجل الخطوات:** الخمس فحوص الصلبة عبرت + الراوتر (158) — «نتيجة الفحص: نجاح — كل الفحوص الصلبة عبرت (بلا أي استهلاك موارد)».
- **السجلات العامة:** كل القيم السرية ظهرت `***` (بما فيها خطوة `add-mask` الدفاعية) — لا قيمة سرية في أي سطر.
- ملاحظة تشغيلية: من نطاقات IP ثابتة (بيئات محلية) قد يظهر قيد معدل 429 عابر على `huggingface.co` — السكربت يعيد المحاولة بمدد مدروسة (3 محاولات × 20 ث)، والفحص المرجعي يُجرى داخل Actions حيث لا قيد من هذا النوع.

## 4. كيف يُعاد الفحص (عقد قابل لإعادة التشغيل)

```
GitHub → Actions → «Infra — فحص اتصال HF/Kaggle (يدوي)» → Run workflow
```

أو من أي بيئة بها المتغيرات الثلاثة: `python3 scripts/infra_check_hf_kaggle.py` — الفحوص الصلبة (HF-1/HF-2/KG-1/KG-2) تخفق البناء عند أي انحراف؛ HF-3 مرن (قيد المعدل لا يخفق). يعاد الفحص عند: تدوير أي مفتاح · تغير حصص مزود · قبل بدء M2 · دوريًا مع مراجعة الحالة.

## 5. ما لم يُفعل عمدًا (حدود هذه الدفعة)

| غير مفعّل | السبب |
|---|---|
| أي تدريب أو kernel على Kaggle | خلف استكمال M1 + D-5 (فئتا القائمة — M2 تحسم الأساس) |
| أي توليد استدلال عبر مزودي HF | «فحوص دخان» فقط عند الحاجة؛ السرد هنا بلا استهلاك — وM2 تقيس فعليًا |
| تنزيل أي نموذج أساس | يتبع D-5؛ الترخيص Apache-2.0/MIT حصرًا (ADR-0011) |
| رفع أي أوزان إلى المستودع الخاص | لا أوزان بعد — المستودع هدف جاهز مُوثق بلا محتوى |
| أي جدولة للسير اليدوي | سير يستخدم أسرارًا = يدوي فقط (SECURITY §8.6) |
| أي تعديل على إنتاج Alkemos أو مزوديه | محظور دائمًا — كل الاتصالات أعلاه خارج نطاق الإنتاج كليًا |

## 6. الأثر على الخطة

- البند المعلق «حسابات مجانية للمسار [مالك]» **محسوم** (STATE §4) — M2 تجد البنية جاهزة.
- الحصة المقيسة حية (30 GPU-س/أسبوع + 20 TPU-س) تُغذي حسابات إيقاع M3 في `COST_MODEL.md` بأرقام مقيسة لا موثقة فقط (القانون: الحصص قابلة للتغيير بلا SLA — دفعة 5).
- المخاطر: R-18 (تغير حصص Kaggle) تخفيفه ساري؛ خطر جديد R-38 (سير أسرار في مستودع عام) سُجل بتخفيفاته.
- الموارد المجانية في STATE §3 تحدثت بالقياس الحي (كانت موثقة فقط).
