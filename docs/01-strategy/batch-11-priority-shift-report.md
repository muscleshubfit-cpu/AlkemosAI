# تقرير دفعة 11 — تحويل الأولوية الاستراتيجية (ADR-0021): مدرب لياقة شخصي ذكي، وتأجيل المحتوى وSEO

> التاريخ: 2026-11-22 (UTC) · القرار: أمر المالك الاستراتيجي المعتمد — [ADR-0021](../../decisions/ADR/ADR-0021-strategic-priority-ai-personal-trainer.md) · النطاق: وثائق وحوكمة فقط — **لا تدريب ولا توليد ولا استهلاك GPU ولا أي التزام مالي ولا مساس بإنتاج Alkemos ولا حذف أي أصل قائم**.

## 1. ما الذي تغير (الخلاصة)

| المحور | قبل (v2.1) | بعد (v2.2 — ADR-0021) |
|---|---|---|
| الهدف الأساسي | نموذج متخصص + خبرة SEO/GEO/AEO متراكمة بالتوازي | **نموذج = مدرب لياقة شخصي ذكي بمستوى احترافي عالمي** — هدف حصري للجهد الحالي |
| مسار C4 (خبرة SEO/GEO/AEO) | مخطط بعد C1+C3 | **⏸ مؤجل بالكامل** إلى مرحلة لاحقة (أصوله محفوظة، واستئنافه بقرار مالك بعد نضج النموذج) |
| بذور seo-skills (30 مهارة) | استيرادها بذرةً لبداية C3 | **مؤجلة** — نظام المهارات (C3) يبقى للقدرات الداعمة للتخصص |
| `sft-blog-style-ar.jsonl` | محجون بـD-15 فقط | **مؤجل استراتيجيًا** (D-15 يبقى نافذًا تقنيًا لجداول المحتوى الأخرى) |
| قرار D-12 (تصدير GSC) | معلق — متوسط | **مؤجل** تبعًا لتأجيل C4 (كان لقياسه) |
| أولويات المعرفة/البيانات/المهارات | بترتيب جرد الأصول | **ترتيب تخصص جديد بست درجات** (تغذية ← تدريب ← تحليل حالات ← تواصل ← استدلال ← مراجع) |
| سياسة اللغة | فصحى + إنجليزية | فصحى + **مصرية (جديدة)** + إنجليزية |
| معايير التقييم | بطارية v0 (162 حالة من مهام المنصة) | نفس البطارية + **خريطة توسع موجهة** بعشرة أبعاد لأداء المدرب (تُبنى تدريجيًا قبل تدريب كل مجال) |
| تسلسل بناء النموذج | M1 ← M2 ← D-5 ← M3 ← M4 | **بلا أي تغيير** (قيد صريح في القرار) |

## 2. المهام التي أصبحت أولوية الآن

1. **استكمال M1 وإغلاقها الرسمي:** أركان G-M1 الثلاثة متحققة فعلًا (بطارية موقعة ✓ توثيق مصدر/ترخيص ✓ أول دورة G-K ✓) — وبند `sft-blog-style-ar` المؤجل استراتيجيًا لم يعد بندًا متبقيًا في M1، فالإغلاق الرسمي صار متاحًا للدفعة التنفيذية التالية وفق البروتوكول (مراجعة ← STATE ← commit).
2. **سد فجوات بيانات التخصص (PLAN §5.6):** حوار العميل متعدد الأدوار (استشارة/متابعة/تعديل) · **العربية المصرية** (لا وجود لها في البيانات الحالية إطلاقًا) · حالات تحليل التقدم والتعافي · حالات اكتشاف الأخطاء والتناقضات في الخطط · عمق علم التدريب خارج البرامج السبعة (عبر C2 بمصادر موثقة الترخيص) · سيناريوهات الإحالة للمختص الطبي. كلها عبر بوابات G-K/G-S القائمة وقانون «نمو البطارية قبل التدريب».
3. **نمو البطارية نحو أبعاد المدرب (المواصفة §6 الجديدة):** الأبعاد العشرة الموثقة في ADR-0021 §4 — تُضاف كمجموعات حالات جديدة قبل تدريب أي مجال جديد منها.
4. **C1 مستمر** (مراقب المصدر — يغذي كل المعرفة بلا تمييز) و**C2** يبدأ بترتيب أولويات بحث وفق الدرجات الست، و**C3** لنظام المهارات بالقدرات الداعمة للتدريب/التغذية/التواصل.
5. **M2 كما هي مجدولة:** قياس المرشحين على البطارية ثم حسم D-5 — لا تغيير في القائمة أو الترتيب.

## 3. المهام المؤجلة (سجل التأجيل — PLAN §10-ج)

## 4. أثر القرار على المراحل التالية

- **M1:** البند المؤجل الأخير (`sft-blog-style-ar`) خرج من نطاقها بالتأجيل — جاهزة للإغلاق الرسمي بالدفعة التالية.
- **M2/M3/M4:** التسلسل والبوابات كما هي حرفيًا؛ الأثر الوحيد هو توجه توسع البطارية وبيانات الدفعات القادمة نحو أبعاد المدرب، مع بقاء قائمة المرشحين وفئتيها (D-5) دون تغيير.
- **مسار C:** C1 نشط كما هو · C2 أولويته البحثية تعيد الترتيب وفق الدرجات الست · C3 يبقى كنظام (بذوره SEO مؤجلة) · C4 مؤجل بالكامل.
- **الحوكمة:** ADR-0021 مسجل · D-12 مؤجل · R-39/R-40 أضيفا للسجل · VISION/PLAN/ROADMAP/FOUNDATION/STATE/README ووثائق datasets/evaluation/skills/memory/research كلها متسقة مع القرار.

## 5. الفحوص المنفذة في هذه الدفعة

- فحص اتساق وثائقي: مسح ذكرى C4/SEO/المقالات عبر المستودع بعد التعديل — كل موضع إما محدث بحالة التأجيل أو مرجع تاريخي لا يعدل (ADRs وخط الأساس وسجل التعلم).
- اختبار طفرة بوابة G-K (`scripts/test_gk_gate_mutations.py`): **26/26** — البوابة سليمة ولا بطاقة مسها التغيير.

- مسح أسرار للفروق قبل الدفع (SECURITY §1) — نظيف.
