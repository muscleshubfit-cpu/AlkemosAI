# ADR-0020 — تفعيل حسابي Hugging Face وKaggle: الأسرار في GitHub Secrets والتحقق القراءة-فقط

> الحالة: مقبول (تنفيذ أمر المالك المباشر 2026-11-22 UTC — دفعة 10؛ ضمن نطاق D-11 الصادر: مجاني/CPU حصرًا) · التاريخ: 2026-11-22 (UTC) · صاحب القرار: المالك (الأمر) — الوكيل (التنفيذ والتوثيق)

## السياق

1. أمر المالك (2026-11-22 UTC): «تابع تنفيذ مشروع AlkemosAI باستخدام حسابي Hugging Face وKaggle اللذين تم إنشاؤهما حديثًا» — مع سبعة قيود: تحديد الاستخدام العملي ضمن البنية الحالية · دمج HF للنماذج وموفري الاستدلال والتخزين المجاني · دمج Kaggle لموارد GPU المجانية ضمن حدودها · وضع المفاتيح في GitHub Secrets بالأسماء المحددة · اختبار الاتصال والصلاحيات دون استهلاك مدفوع أو تجاوز الحصص · **لا مفاتيح في الكود أو الملفات ولا طباعة في السجلات** · تحديث التوثيق بما يعكس التنفيذ الفعلي.
2. البنية أعدّت المكان مسبقًا بلا قرار جديد: ADR-0009 يحدد HF Hub الخاص «الساق الأولى» لثلاثية تخزين الأوزان، وADR-0010 يحدد Kaggle «بيئة التدريب الأساسية» (30 GPU-س/أسبوع بتصميم قابل للاستئناف)، وADR-0014 يفصل الاستدلال المرجعي عن التدريب، وADR-0011 يقصر الأساس على Apache-2.0/MIT. البند المعلق رقم 6 في STATE §4 («حسابات مجانية للمسار [مالك]: Kaggle + Hugging Face») كان ينتظر إنشاء المالك للحسابات — **وقد أُنشئت فأصبح هذا القرار تنفيذًا مباشرًا لا جسرًا جديدًا**.
3. القيد الحاكم من D-11 ما زال نافذًا: لا تدريب أوزان قبل استكمال M1 وقياس M2 (D-5). فالتفعيل هنا **جاهزية بنية تحتية فقط** — لا تدريب ولا توليد.

## القرار

1. **تفعيل Hugging Face (حساب `Alkemos`) بثلاثة أدوار محددة:**
   - **مستودع الأوزان الخاص `Alkemos/alkemosai-weights`** (أُنشئ خاصًا فعليًا 2026-11-22 وبتوقيع README يوثق دوره): الساق الأولى من ثلاثية ADR-0009 — التخزين الأول لأوزان المشروع المملوكة عند بدء M2/M3 (بلا أوزان فيه اليوم — عقد «لا يُعتبر محفوظًا حتى تكتمل السوق الثلاث»).
   - **النماذج**: قناة تنزيل الأساس العام (Apache-2.0/MIT فقط — ADR-0011) عند بدء M2 — لا تنزيل في هذه الدفعة.
   - **موفرو الاستدلال**: طبقة «فحوص دخان» فقط كما في ZERO_COST_PLAN §3.1 — وصول الراوتر تحقق بالسرد (158 نموذجًا مسرودًا) **بلا أي توليد وبلا استهلاك أي رصيد**؛ لا اعتماد تشغيلي عليها.
2. **تفعيل Kaggle (حساب `AlkemosAI`) بيئة تدريب أساسية وفق ADR-0010**: مفتاح KGAT واسم المستخدم في الأسرار؛ الحصة قُرئت حية **30 GPU-س/أسبوع (0 مستخدمة) + 20 TPU-س/أسبوع، تجدد 2026-11-28T00:00:00Z** — قراءة-فقط لم تستهلك ثانية GPU. لا kernel يُدفع ولا تجربة تدريب قبل M1 كاملة + D-5.
3. **الأسرار في GitHub Repository Secrets حصريًا** بالأسماء التي حددها المالك: `HF_TOKEN` · `KAGGLE_USERNAME` · `KAGGLE_KEY` — أُضيفت عبر REST API بتشفير libsodium (ختم مغلق بمفتاح المستودع العام)، **ولم تُكتب قيمة أي منها في أي ملف أو كود أو سجل** (SECURITY §1/§7؛ القيم في السجلات تظهر مموهة `***` — تحقق فعلي).
4. **نموذج مصادقة Kaggle المكتشف موثقًا (قياس حي 2026-11-22)** — لأن سكربتات M2 ستبني عليه:
   - خدمة `datasets` تقبل **HTTP Basic** (اسم المستخدم + مفتاح KGAT).
   - خدمة `kernels` (التدريب والحصص) **ترفض Basic وتقبل `Authorization: Bearer <KGAT>` فقط**.
   - نقطة التحقق القاطعة من صلاحية المفتاح: `security.OAuthService/IntrospectToken` — المفتاح الصحيح يعيد `{active: true, username, scope}` والمفتاح الخاطئ يعيد 404 (أي أن سرد البيانات العامة «200» وحده **لا يثبت** المصادقة — أُثبت ذلك بمصفوفة سلوكية: بلا اعتماديات وباعتماديات خاطئة تعيد نفس استجابة 200).
5. **سير تحقق يدوي بلا جدولة** (`.github/workflows/infra-connectivity-check.yml`): `workflow_dispatch` فقط — لا جدولة ولا مشغّل دفع ولا PR؛ صلاحيات `contents: read` فقط؛ `add-mask` دفاعي قبل التشغيل؛ السكربت يقرأ من متغيرات البيئة فقط ويطبع الأسماء والحصص وحالات الاستجابة فقط. استثناء موثق من قاعدة R-35 (المراقب بلا أسرار): هذا السير **يستخدم أسرارًا لكنه يدوي فقط** — البوابة: تشغيله لا يستهلك شيئًا (قراءة-فقط) وسجلاته مكشوفة للعامة فلا يطبع إلا المموه والمسؤول.
6. **حدود التفعيل (صريحة):** لا تدريب أوزان · لا توليد استدلال (لا استهلاك رصيد) · لا استهلاك GPU (0 ثانية) · لا تنزيل نماذج · لا كتابة في أي خدمة سوى إنشاء مستودع الأوزان الخاص وتوثيقه · لا أي التزام مالي · لا مساس بإنتاج Alkemos ولا بمزوديه.

## النتائج

- البند المعلق «حسابات مجانية [مالك]» في STATE §4 **محسوم** — الحسابات موجودة ومتحقق منها؛ M2 تجد البنية جاهزة (مستودع أوزان + بيانات اعتماد صحيحة في الأسرار + إيقاع الحصة مقيسًا).
- نطاق M2 لا يتغير: بدء التدريب ما زال خلف استكمال M1 وحسم D-5 (فئتا القائمة القصيرة) — هذا القرار جاهزية فقط.
- إدارة الحصص: قيد معدل HF على نطاقات IP متغيرة أُدير داخل السكربت بإعادة محاولة مدروسة (429 عابر ≠ فشل صلاحية) — ولهذا فالتحقق المرجعي يُجرى داخل Actions لا من IP ثابتة.
- R-38 يُسجل في سجل المخاطر: سطح خطر جديد (سير يستخدم أسرارًا في مستودع عام) بتخفيفاته الموثقة أعلاه.
- القاعدة الدائمة (SECURITY §7) تنطبق على هذه المفاتيح كما غيرها: أُشركت في محادثات وكلاء فأمر تدويرها بعد اكتمال الحاجة إليها بيد المالك لدى مزوديها مباشرة — المفاتيح في Secrets تُحدَّث بنفس مسار الإضافة الموثق هنا.
