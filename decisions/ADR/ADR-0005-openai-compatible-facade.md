# ADR-0005 — واجهة متوافقة مع OpenAI كعقد تكامل مقترح

> الحالة: مقترح (ينهيه اعتماد G2 أو رفضه) · التاريخ: 2026-11-21 · صاحب القرار: وكيل التأسيس (تصميم) — الاعتماد النهائي للمالك

## السياق
المرحلة 8 تتطلب تكاملًا مع Alkemos بأقل تعديل إنتاجي ممكن. خط الأساس أثبت أن المنظومة الحالية موحدة النقل خلف محرك واحد (`callFreeAIFallbackChain`) وأن التراجع بمتغير واحد نمط مجرب. المعيار الفعلي للمجال كله اليوم هو واجهة OpenAI Chat Completions.

## القرار (المقترح)
عقد المحرك الخارجي: **واجهة متوافقة مع OpenAI** ‏(`/v1/chat/completions` + `/v1/embeddings`) مع امتدادين: رأس `X-Alkemos-Task` (توجيه المهمة مركزيًا) وmetadata بالاستجابة `{provider, model, qualityTier, cost}`. النتيجة: استهلاك Alkemos يتكامل نظريًا بتغيير base_url ومفتاح ورأس — دون لمس بوابات الحصص والسلامة القائمة.

## الخيارات التي فُحصت
عقد API مخصص بالكامل: رُفض — يعني تعديل استهلاك أعمق في إنتاج حساس. الاكتفاء بمواصفات موزع أوزان (خوادم النماذج كما هي): رُفض — يفقد طبقة السياسة والحصص والتوجيه المركزي.

## النتائج (إن اعتُمد)
أقل تعديل إنتاجي ممكن + استبدال أي نموذج شفاف (عمود الملكية 9) + توافق فوري مع أدوات القياس القياسية. أثر مراقب: «التوافق» لا يعني «التطابق الكامل» — تُوثق الامتدادات والفروق صراحة في OpenAPI spec عند G2.
